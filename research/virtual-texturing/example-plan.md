# Virtual Texturing Example Plan

Date: 2026-06-28

This is the examples-app handoff for a simple virtual-texturing route that can
land before renderer virtual-texturing hooks exist. It is intentionally a
research fixture preview, not a real renderer virtual texture demo.

## Simplified Examples Route

- Route: `/labs/virtual-texturing`
- Catalog id: `virtual-texturing-terrain`
- Title: `Virtual Texturing Terrain`
- Section: `labs-prototypes`
- Component file:
  `apps/examples-react/src/examples/cases/VirtualTexturingTerrain.tsx`
- Component export: `VirtualTexturingTerrain`
- Prototype visual surface: image/SVG preview, not a WebGL VT canvas
- Future real visual surface: `canvas`

The examples rewrite worker can copy the research fixture into the examples
public asset tree when it is ready to touch `apps/examples-react/**`:

```text
research/virtual-texturing/demo-assets/manifest.json
research/virtual-texturing/demo-assets/example-fixture.json
research/virtual-texturing/demo-assets/preview/terrain-pages-overview.png
research/virtual-texturing/demo-assets/preview/page-cache-debug-overlay.svg
research/virtual-texturing/demo-assets/stats/camera-pan-stream.json
```

Suggested destination:

```text
apps/examples-react/public/virtual-texturing/
```

Keep page PNGs out of the initial simplified example unless the app needs a
page-browser detail view. The preview image and overlay are enough for the
menu/preview/source shape.

## Prototype Source Shape

`VirtualTexturingTerrain.tsx` should stay boring and explicit:

```tsx
type Fixture = {
  example: {
    title: string;
    mode: string;
    rendererStatus: string;
  };
  assets: {
    overviewPreviewUri: string;
    cacheOverlayPreviewUri: string;
    manifestUri: string;
    statsUri: string;
  };
  statsSummary: {
    exactHitRatio: number;
    maxUploads: number;
    totalEvictions: number;
    maxSeamCandidates: number;
  };
};

export function VirtualTexturingTerrain() {
  // Fetch /virtual-texturing/example-fixture.json or import the copied JSON.
  // Render two previews plus a small stats table. Do not construct renderer VT
  // nodes or imply that page-table sampling is live.
}
```

The preview should show:

- the generated material overview image
- the cache/debug overlay SVG
- fixture stats from `example-fixture.json`
- links or source text naming the copied manifest and stats JSON
- a visible status string: `Research fixture preview; renderer VT hooks are not
  active in this route.`

Do not add or reference a public `VirtualTextureNode`. The author-facing shape
is asset and material data only.

## Assets Used

- `manifest.json`: virtual texture dimensions, page size, border padding,
  mip count, hashes, sampler policy, and demo budget.
- `example-fixture.json`: compact route metadata, acceptance criteria, and
  stats summary generated by `generate-example-fixture.mjs`.
- `preview/terrain-pages-overview.png`: primary route preview.
- `preview/page-cache-debug-overlay.svg`: secondary debug overlay preview.
- `stats/camera-pan-stream.json`: source stats for fixture cards and future
  renderer comparison.

## Visual Acceptance

The simplified example is acceptable when:

- `/labs/virtual-texturing` appears in the examples menu with title
  `Virtual Texturing Terrain`.
- The preview displays the terrain overview without distortion.
- The overlay preview is visible and legible at desktop and mobile widths.
- The route shows fixture stats for exact hit ratio, max uploads, evictions,
  dirty page-table entries, and seam candidates.
- The source panel includes the fixture status string and does not mention a
  public renderer VT node.
- Browser smoke can assert nonblank preview images and the copied JSON title.

The route must not claim live virtual texturing. It is a preview of the asset
contract and debug UX until renderer internals can perform page-table lookup,
physical-cache residency, and per-frame streaming.

## Future Migration

When private renderer hooks exist, keep the route, catalog id, and title. Migrate
the implementation in place:

- Replace the static preview with a Royal scene rendered to `canvas`.
- Keep the manifest/material authoring shape and let renderer internals lower it
  into page-table, physical-cache, upload, shader, and debug resources.
- Add private page-table texture allocation and dirty texel updates.
- Add a physical page cache atlas with border-padded page uploads.
- Add resident fallback lookup so missing exact pages sample the best resident
  parent mip.
- Add frame stats for requests, exact hits, misses, uploads, upload bytes,
  evictions, dirty page-table entries, fallback samples, and seam candidates.
- Preserve the low-mip fallback path for unsupported capabilities.
- Keep algorithm details private; do not introduce public algorithm scene nodes.

The real demo is ready only when the renderer can show live residency changes
and the debug overlay numbers are produced by the renderer path rather than the
research fixture JSON.
