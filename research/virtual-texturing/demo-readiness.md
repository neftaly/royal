## Demo Gates

The browser demo should not land until these are true:

- [ ] Renderer internals can create and update a private page-table texture.
- [ ] Renderer internals can upload border-padded pages into a physical cache.
- [ ] Material binding can route a base-color resource through virtual texture
  indirection without adding public scene nodes.
- [ ] Scheduler exposes frame stats for requests, hits, misses, uploads,
  evictions, dirty page-table entries, fallback samples, and seam candidates.
- [ ] Capability fallback renders a fixed low-mip material when virtual
  texturing is unavailable; WebGL1 is reported as unsupported, not reduced.
- [ ] Debug overlay can be toggled without changing the author-facing scene.

Readiness targets for the first real route:

- At least 95% exact page-hit ratio after warmup during slow pan.
- No more than 8 uploads per frame.
- Less than 2 ms estimated texture upload time per frame on desktop WebGL.
- Page-table updates stay proportional to uploads plus evictions.
- Zero generated-border mismatches for checked pages.
- Seam stress mode makes resident-mip mismatches visible and counted.

### Scene

The scene displays a large generated terrain/material surface viewed from a
low oblique camera. The material is backed by the virtual texture asset in the
fixture shape, scaled up to the full demo budget. It should look like a painted
landscape with altitude bands, slope streaks, roads or river scars, and sparse
decal stamps. The initial camera path pans across at least three biome/color
regions so undersized caches visibly produce fallback mips and replacement
uploads.

Use author-facing resources shaped like:

```ts
const terrainAlbedo = {
  kind: "virtual-texture-asset",
  id: "royal.generated-terrain-material.vt-demo",
  manifestUri: "/virtual-texturing/manifest.json",
};

const terrainMaterial = {
  kind: "material",
  baseColorTexture: { asset: terrainAlbedo.id },
  fallbackBaseColor: [0.43, 0.48, 0.31, 1],
};
```

The renderer can lower those resources into page-table, cache, upload, and
shader details privately.

### Controls

- Play/pause camera pan.
- Pan speed.
- Cache slot budget.
- Upload page budget.
- Debug overlay visibility.
- Seam stress mode.
- Force fixed low-mip fallback.

### Debug Overlay

The overlay must show:

- Physical cache slots with page id, mip, and visible/resident/free state.
- Page-table dirty entry count.
- Requested pages and queued pages after budget.
- Exact hits, misses, fallback samples, and hit ratio.
- Upload pages, upload bytes, evictions, and estimated upload time.
- Resident-mip seam candidates.
- Selected capability path: WebGL2 virtual texture, fixed low-mip fallback, or
  unsupported WebGL1.

### Tests

- Catalog test includes `virtual-texturing-terrain` and route
  `/labs/virtual-texturing`.
- Browser smoke confirms a nonblank canvas, the route title, and source text.
- Visual smoke captures the overlay enabled and disabled.
- Renderer-internal tests cover page-table entry encoding, resident fallback
  lookup, cache eviction invalidation, upload budget capping, and low-mip
  fallback selection for unsupported capabilities.
- Research report check remains runnable while the full demo asset scale is
  still generated outside package APIs.

## Research Report Artifact

Generate or check the compact report with:

```sh
node research/virtual-texturing/generate-demo-report.mjs
node research/virtual-texturing/generate-demo-report.mjs --check
```

Outputs:

- `demo-assets/report/index.html`
- `demo-assets/report/virtual-texturing-demo-readiness.svg`

The report is generated from the existing manifest, preview assets, cache
overlay, camera-pan stream, and page metadata. It also verifies the manifest
hashes for every page, preview, and stats file before writing or checking the
report.
